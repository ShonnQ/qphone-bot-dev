2. 综合描述

2.1 系统目标

人在对话里交代一件事。事由虚拟机里的控制程序，在旁边那部云 Android 上做完。卡住或做完，才回到对话。屏幕不是主界面。

2.2 系统概述

三块，调用方向固定。

程序 位置 现在
客户端 薄壳，形态未定（2026-10-22 删 Rakazo） 未建。只发交代、只收进度与结果，不含 agent、不带电脑容器。
控制程序 近云机一侧（正式在 Ubuntu 虚拟机；临时在 Mac） 未接。框架定 Mobilerun。
云机 redroid 容器（正式）／天翼云手机（临时） 临时载体已实测可操作。

Mac 不操作云机。操作只发生在虚拟机内部：控制程序调用本机 adb。人要接手看屏幕，也在虚拟机这边，不把画面转到 Mac。

2.3 运行环境

项 实际
环境 正式：现有远程 Windows 上的 Ubuntu 虚拟机。临时（2026-10-22 起）：天翼云手机（Android 13 / SDK 33 / arm64-v8a，Mac 转发口每次会话都变）。
虚拟机内存 8G。这部上稳的只有一部云机。
云机镜像 redroid/redroid:13.0.0_64only-latest
云机系统 Android 13，x86_64
云机入口 虚拟机内 127.0.0.1:5555，adb
客户端 薄壳，形态未定。候选：Telegram / Hermes 桌面顶（零开发），或自写 Tauri / Electron 薄壳。
对照 同一台虚拟机里的 A9。留着。不作为本设计的运行程序。

2026-10-19 已核实：在虚拟机内对 127.0.0.1:5555 点相册图标，相册打开。从 Mac 经转发发回主屏，也能回到桌面。同一条转发上，看屏连接失败过，大截图传断过。所以联调不走 Mac 转发。

3. 系统详细设计

3.1 redroid 容器

3.1.1 程序特征

现成容器。镜像名 redroid/redroid:13.0.0_64only-latest。不是本项目编译出来的可执行文件。

3.1.2 功能

提供一部可操作的 Android 13。装应用、打开应用、接受点击、给出画面，都通过 adb。不在本容器里放控制逻辑。

3.1.3 输入 / 输出

方向 项 说明
输入 adb 连接 仅虚拟机内 127.0.0.1:5555
输入 adb install 安装指定安装包
输入 adb shell input 点击、按键
输入 adb shell am 打开应用
输出 命令返回 成功或失败原因
输出 screencap 当前画面。给人接手时用，不作为主界面

不向 Mac 提供屏幕和控制入口。

3.1.4 数据结构

容器内的应用数据在容器数据盘。关机不删这盘。清空要另下指令。盘的路径未定，见附录 B。

3.1.5 调用关系

被虚拟机内的控制程序调用。不被 Mac 上的客户端调用。

3.1.6 算法

无自有算法。

3.1.7 限制

一部。8G 虚拟机上不并行开第二部。x86 上的 ARM 应用，没在这部上打开过，不算能用。

3.2 控制程序

3.2.1 程序特征

未建。运行位置：云机所在的 Ubuntu 虚拟机。框架：Mobilerun 开源框架，不是它的托管云。尚未接入这部 redroid。

3.2.2 功能

接收一句交代。在本部云机上做完，或说出失败原因。做的过程中回报进度。需要人看屏幕时，发出要人，并停在虚拟机侧。做完发出结果。开机、关机的状态要说得清。

人不用填端口。端口就是本机 127.0.0.1:5555。

3.2.3 输入 / 输出

方向 项 说明
输入 交代 来自客户端的一句话，或一个安装包 / 应用名
输出 进度 正在做哪一步
输出 要人 卡住。人到虚拟机侧看屏幕，不转到 Mac
输出 结果 做成，或失败原因
输出 状态 开、关、能不能操作
对被控机 adb 只连 127.0.0.1:5555

这五种是对话来回的全部。字段名未定，见附录 B。

3.2.4 数据结构

未建。不在本文编一套假的表。

3.2.5 调用关系

客户端把交代送到虚拟机里的本程序。本程序只调用本机 adb，不调用 Mac。本程序不把 scrcpy 或屏幕流转到 Mac。

通道（2026-10-22 定，实现未做）：POST /turn 送一句交代，回事件流 progress / needs_human / result / status。壳只认这四种事件，不认云机地址、不认 adb。控制程序跑在哪台机、云机是容器还是租用实例，壳都不需要知道。

3.2.6 算法

未设计。第一版只要求做透一个场景。场景用哪个应用，见附录 B。

3.2.7 处理顺序

  1. 收到交代。
  2. 确认云机可操作。不可操作则返回状态和失败原因，停止。
  3. 若交代是安装或打开，经本机 adb 做完，返回结果。
  4. 若要在真实界面上点一步，经本机 adb 点。点完把这一步的结果返回对话。
  5. 点不下去，发要人，人在虚拟机侧接手。
  6. 收到关机交代，关掉这部，返回状态。

3.3 客户端

3.3.1 程序特征

薄壳，未建。只做三件事：收一句交代、显示进度、显示结果（含要人）。不含 agent、不带电脑容器、不依赖 docker。

2026-10-22 原拟用现成 Rakazo 桌面，已完整删除（容器、镜像、数据卷、源码目录一并清掉）。理由：Rakazo 自带 agent 与「电脑」容器，与「客户端只系壳」冲突；两层 agent 串埋会 token 双花、步数放大、出错分不清哪层。同日亦否决 dsh 桌面（同属自带 agent 的 harness，不是壳）。候选形态：① 先用 Telegram / Hermes 桌面顶；② 自写 Tauri / Electron 薄壳。未定，见附录 B7。

3.3.2 功能

给人一个对话入口。发出交代。显示进度、要人、结果、状态。不在 Mac 上打开云机画面，不在 Mac 上点云机。

3.3.3 输入 / 输出

方向 项
输入 人输入的交代
输出 发给虚拟机控制程序的交代
输入 控制程序返回的进度、要人、结果、状态
输出 显示给人

壳只调 POST /turn 与事件流。壳不连 adb，不认云机是怎么来的。

3.3.4 数据结构

未定。壳只保留对话显示，不存云机状态，不存 adb 地址。

3.3.5 调用关系

人调用客户端。客户端只调用虚拟机里的控制程序。客户端不调用 127.0.0.1:5555，那个地址不在 Mac 上。

3.3.6 算法

无。

4. 用户界面详细设计

4.1 界面结构

主界面是壳里的对话。本文不重画这个界面。

云机画面不是主界面，也不出现在 Mac。要人接手时，画面在虚拟机侧打开。

4.2 处理流程与约束

人在对话里输入。看到要人之后，到虚拟机侧看那部云机，不要求把画面转到当前 Mac。

约束：壳不写死平台，也不写死云机来源。换云机（容器 ↔ 租用实例）只改控制程序，壳一行不动。两边的接法是第 3.2.5 节的 POST /turn。

模型地址由人在客户端里填写。本文不代填。
