方案摆位 / 尺寸好唔好
A 流程图右侧，宽 150px（≥1180px 用 170px），9:20 竖窗 一眼对照「高亮节点 ↔ 真机画面」；唔遮任何东西；≤900px 自动落到流程下面 占用横向空间，流程要收窄（1280px 下流程仍有 1006px，实测够）
B 流程图下方，通栏高 46–60px 零横向占用；流程保持原宽 手机是竖的，横条只能切一条边，睇唔到全屏；同过程图上下分离，对照要来回扫
C 右下角浮窗，宽 64–80px，可拖 最省空间；似直播小窗 会遮住日志／输入框；要写拖动 + 吸边逻辑，成本最高

3 · 窗内规格（三个方案共用）

项规格
比例720 : 1600（云机真实分辨率），竖窗 9:20，不裁切（object-fit:cover 同比例下等于不裁）
标题行云机实况 + 状态点（在线绿 / 离线红）+ 等宽小字
底行左：720×1600　右：最后一帧时间 10:52:31
边框1px，色 acc 30% 混 line；圆角 4px（配合科技风切角）
离线态画面区盖 55% 黑 + 居中 云机离线，状态点转红
抓帧可见时 2.6s／帧；分页被遮住降 8s／帧；单帧 6s 超时即跳过，不阻塞
联动act 事件（真正点落去）即刻抓一帧，不等定时器

4 · 同过程图嘅对照关系

过程图状态实况窗行为
