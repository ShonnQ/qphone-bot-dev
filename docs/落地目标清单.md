# QPhone Bot 落地目标清单

> 定位：唔追求「咩都做到」。一条目标 = 一个讲得清嘅起终点 + 一个 adb 机核得到嘅成功判定。
> 每条目标验收时都要**实测跑通**，唔靠模型自述「做完」。

---

## G1 音乐 App → 目标歌单 → 指定歌曲 → 点播

**一句话触发**
「开网易云，播『粤语经典』歌单入面嘅〈海阔天空〉」

**起点**：任意画面（锁屏、桌面、别的 App 都算）
**终点**：目标歌曲**正在播放**（唔系停喺歌单、唔系停喺详情页）

**成功判定（全部要 adb 机核）**
1. `dumpsys media_session` 有 active session，且 `pkg` = 目标音乐 App
2. session `state = PLAYING`（唔系 PAUSED / STOPPED）
3. session metadata 嘅 `title` 命中歌名（歌手可选）
4. 截图留档（人眼复核一次，之后可省）

**要用到嘅能力**
| 能力 | 现况 |
|---|---|
| 打开指定 App | 已有（L0 `am start -W`） |
| 中文落字（搜歌名/歌单名） | 已有（ADBKeyBoard broadcast） |
| 列表内滚动查找（歌单 30+ 首） | **未接**（`scroll` 未实现，现在靠 L2 视觉） |
| 歌单 → 歌曲条目文本比对 | **未做**（L1a snapshot 有 rect，可做行匹配） |
| 播放状态判定 | **未做**（`media_session` 未接入） |

**未决问题（要老板答）**
- 边个音乐 App？（网易云 / QQ音乐 / Spotify / 本机自带）
- 有冇可用账号？歌单系自己嘅还是公开歌单？
- 歌单名同歌名系固定，定每次都唔同？
- redroid 容器有冇音频输出？（**未验**，只影响「听到」，唔影响状态判定）

**风险**
- redroid 无 GMS，部分音乐 App 依赖 Google 服务会闪退（**未验**）
- VIP 歌曲可能只播 30 秒试听 —— 成功判定要接受「试听」定当失败，待定

## G2 只有移动端嘅 App → 发布带图动态（例：Soul 发今日动态）

**点解值得单独立一条**：呢类 App **冇网页版、冇公开 API**，只能靠「真机/云机 + 人手式操作」——正正系「端云最后一公里」嘅核心价值所在。

**一句话触发**
「去 Soul 发条今日动态：<文字内容>，配呢张图」

**起点**：任意画面（含未开 Soul、锁屏）
**终点**：动态**已经发布成功**，唔系停喺编辑页、唔系停喺草稿

**成功判定（adb 机核，三层递进）**
1. 发布后回到「我的 → 动态」列表，`snapshot` 文本命中**本次文字内容**（取前 10 字做 key）
2. 该条目附带图片（列表里出现图片节点 / 缩略图）
3. 列表第一条时间显示「刚刚 / X 分钟前」
4. 截图留档，人眼复核一次

> 判定原则：**唔接受「点咗发布按钮」当作成功**。要有「回到列表见得到」呢一步。

**要用到嘅能力**
| 能力 | 现况 |
|---|---|
| 打开指定 App、回到前台 | 已有（L0） |
| 中文长文本输入（含换行、emoji） | 单行已有（ADBKeyBoard）；**多行/emoji 未验** |
| 图片送进云机相册 | **未做**（`adb push` + `MEDIA_SCANNER_SCAN_FILE` 广播） |
| 系统相册选择器里选到指定图 | **未做**（靠 L1a/L2 点缩略图） |
| 找到「+ / 发布」入口并进编辑页 | 未做（L2 视觉） |
| 发布后回列表核验 | **未做**（要接 snapshot 文本比对） |

**未决问题（要老板答）**
- 文字内容边个出？（老板每次讲／每天自动生成／固定模板）
- 图片边个出？（老板给图／云机相册已有／生成图后推入）
- 账号：Soul 登录系手机号 + 验证码 → **首次登录要人接管**，之后保持登录？
- 发布频率同时间？（每日一条／手动触发）
- 失败判定：审核不过 / 网络失败 / 草稿未发，三种要分开讲清楚

**风险**
- 登录 + 验证码：一定要人肉一次（接管卡）
- 内容审核：发出去可能被限流/删除，程序只能核到「已发布」，核唔到「已展示」
- 滑块/真人验证：Soul 偶发出现，出现即走接管
- 图片选择器各机型 UI 不同：云机固定用 redroid 自带 `DocumentsUI`，可预测（**未验**）
