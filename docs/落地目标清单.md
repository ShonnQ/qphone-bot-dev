# QPhone Bot 落地目标清单

> 定位：唔追求「咩都做到」。一条目标 = 一个讲得清嘅起终点 + 一个 adb 机核得到嘅成功判定。
> 每条目标验收时都要**实测跑通**，唔靠模型自述「做完」。

---

## G1 音乐 App → 目标歌单 → 指定歌曲 → 点播

**一句话触发**
「开网易云，播『粤语经典』歌单入面嘅〈海阔天空〉」

**起点**：任意画面（锁屏、桌面、别的 App 都算）
**终点**：目标歌曲**正在播放**（唔系停喺歌单、唔系停喺详情页）

**成功判定（全部要 adb 机核）**
1. `dumpsys media_session` 有 active session，且 `pkg` = 目标音乐 App
2. session `state = PLAYING`（唔系 PAUSED / STOPPED）
3. session metadata 嘅 `title` 命中歌名（歌手可选）
4. 截图留档（人眼复核一次，之后可省）

**要用到嘅能力**
| 能力 | 现况 |
|---|---|
| 打开指定 App | 已有（L0 `am start -W`） |
| 中文落字（搜歌名/歌单名） | 已有（ADBKeyBoard broadcast） |
| 列表内滚动查找（歌单 30+ 首） | **未接**（`scroll` 未实现，现在靠 L2 视觉） |
| 歌单 → 歌曲条目文本比对 | **未做**（L1a snapshot 有 rect，可做行匹配） |
| 播放状态判定 | **未做**（`media_session` 未接入） |

**未决问题（要老板答）**
- 边个音乐 App？（网易云 / QQ音乐 / Spotify / 本机自带）
- 有冇可用账号？歌单系自己嘅还是公开歌单？
- 歌单名同歌名系固定，定每次都唔同？
- redroid 容器有冇音频输出？（**未验**，只影响「听到」，唔影响状态判定）

**风险**
- redroid 无 GMS，部分音乐 App 依赖 Google 服务会闪退（**未验**）
- VIP 歌曲可能只播 30 秒试听 —— 成功判定要接受「试听」定当失败，待定

## G2 只有移动端嘅 App → 发布带图动态（**通用能力，Soul 只系其中一个例子**）

**点解值得单独立一条**：呢类 App **冇网页版、冇公开 API**，只能靠「真机/云机 + 人手式操作」——正正系「端云最后一公里」嘅核心价值所在。

**目标定义（通用，唔绑死某一个 App）**
> 任何一个只出手机版嘅 App，只要佢支持「发一条图文动态」，云机就要做得到：开 App → 进发布入口 → 落文字 → 配图 → 发布 → 回列表核验。

**一句话触发**
「去 <App 名> 发条动态：<文字内容>，配呢张图」

**起点**：任意画面（含未开该 App、锁屏）
**终点**：动态**已经发布成功**，唔系停喺编辑页、唔系停喺草稿

**成功判定（adb 机核，四层递进，对所有 App 一致）**
1. 发布后回到该 App 嘅「我的 → 动态/笔记」列表
2. `snapshot` 文本命中**本次文字内容**（取前 10 字做 key）
3. 该条目附带图片（列表里出现图片节点 / 缩略图）
4. 列表第一条时间显示「刚刚 / X 分钟前」；截图留档，人眼复核一次

> 判定原则：**唔接受「点咗发布按钮」当作成功**。要「回到列表见得到」先算完成。

**通用骨架（一次做好，之后每加一个 App 只补「一套 UI 路径」）**

| 步骤 | 通用做法 | 每 App 差异 |
|---|---|---|
| 1 开 App | L0 `am start -W` | package 名 |
| 2 进发布入口 | 找「+ / 相机 / 发布」控件（L1a snapshot 文本匹配） | 入口位置、有无二次选择（图文/视频） |
| 3 落文字 | ADBKeyBoard broadcast（中文/emoji） | 输入框是否要先点一下、有无字数限制 |
| 4 配图 | `adb push` 到 `/sdcard/DCIM/` + 媒体扫描广播 → 打开系统图片选择器 → 选第一张 | 发布器系用系统选择器定自研相册 |
| 5 发布 | 点「发布/完成」 | 是否二次确认、是否可定时 |
| 6 核验 | 回列表 + snapshot 文本比对 | 列表入口路径 |

**示例 App（只是举例，唔系清单）**：Soul（广场 → 发布）、小红书（+ → 图文笔记）、抖音（+ → 图文）、微信朋友圈（发现 → 朋友圈）、微博、闲鱼（发闲置）。

**未决问题（要老板答）**
- **先打穿边一个 App？**（建议只拣一个，做完再复制）
- 文字内容边个出？（老板每次讲／每天自动生成／固定模板）
- 图片边个出？（老板给图／云机相册已有／生成图后推入）
- 账号：多数系手机号 + 验证码 → **首次登录要人接管**，之后保持登录？
- 发布频率同时间？（每日一条／手动触发）

**风险**
- 登录 + 验证码：一定要人肉一次（接管卡）
- 内容审核：程序只能核到「已发布」，核唔到「已展示/未限流」
- 滑块 / 真人验证：出现即走接管
- 图片选择器 UI 各 App 不同（系统选择器 vs 自研相册），要靠 snapshot 适配，唔可以写死坐标
