## 3 本阶段修掉嘅坑（都系会复发嘅）

1. **`.n` 有 `clip-path`** → 任何挂在节点内嘅绝对定位子元素都会被切走。模型框必须挂 `.macwrap`，唔可以挂节点。
2. **CSS 多余 `}`** → 从出错行起整段规则被浏览器丢弃（CSSOM 查得到、Computed 唔生效）。改 CSS 后必须查 CSSOM。
3. **`body{zoom:1.5}` 下 JS 量到嘅视觉 px ≠ CSS px** → 偏移要除以 zoom；量 → 调 → 残余校正，唔可以累积。
4. **`modelName` id 重复**（顶栏 chip 与节点同名）→ `$("modelName")` 只命中第一个，节点永远显示旧值。已拆 `modelNodeName`。
5. **媒体查询睇嘅系 layout viewport（未除 zoom）** → 断点要按物理宽写（用 1560 而唔系 1100）。

## 4 架构事实（避免再搞错）

## 8 会话衔接修复（bug 复盘）

**症状**：任务一开跑，会话里出现一张带进度条嘅卡，但好快消失；任务做完会话又冇任何完成反馈。

**日志证据**：`/tmp/serve8777.log` 有 `BrokenPipeError: [Errno 32] Broken pipe`，位置喺 `emit()` 写 SSE 时 —— 前端 mid-run 断开（刷新 / 切走 / 导航），服务端写唔到。任务线程照跑，但**会话内容只活喺浏览器内存**，断开即全失；重开只见 `/state` 嘅过程图，会话空白；而 `activity` 收到 `done/human` 时旧代码仍会 `if(!taskCard) taskStart()`，于是补出一张「执行中 STEP 00/20」嘅鬼卡，令人以为「气泡闪一下就冇」。

**修法（四层）**

| 层 | 做法 |
|:--|:--|
| 数据 | `serve.py` 加 `HISTORY` + `/history`：`me / chat / task` 三类记录，任务记录带 `id/step/of/phase/detail/msg` |
| 写 | `/turn` 入口记 `me`；chat/clarify 记 `chat`；开跑先建 `task` 记录并 emit `task_started`；`_pub` 每次 step 同步 `phase/step/detail`；完单写 `phase=done|human` + `msg` |
| 推送 | `emit()` 捕获 `BrokenPipeError / ConnectionResetError` → 标记 `alive=False`，后端照跑完、结果照落历史；队列继续 drain 到 `_end` |
| 壳 | 开页 `loadHistory()` 重绘全部气泡与任务卡；`done/human` 相位只 paint 过程图、唔再开新卡；`syncLiveTask()` 每 3 秒同 `/history` 对齐未收工嘅最后一张卡 |

**验证**

1. 开跑 6 秒后中途刷新 → 刷新即刻见「你嘅气泡 + 系统胶囊 + 任务卡（含步数）」；约 20 秒后卡片自动转绿「完成」，附结果文字。
2. 正常跑完后再盯 8 秒 → 任务卡数量稳定（2 → 2），无鬼卡。
3. 跨轮次刷新 → 历史顺序 `me / sys / task / ...` 保持，唔重排唔丢。

### 14.2 本地 redroid 13（跑通，正式形态）

`scripts/redroid-up.sh` 一条命令起：容器 `qphone-redroid` @ `localhost:5556` → 容器内 5555，型号 `redroid13_arm64_only`，Android 13 / SDK 33 / arm64-v8a。

踩过四个坑（全部写进脚本与详细设计 §3.1.8）：

| # | 现象 | 真因 | 解法 |
|:--|:--|:--|:--|
| 1 | 容器 `Exited (129)`、`docker logs` 空白 | 用 `13.0.0-latest`，带 32 位 vendor 二进制；dmesg 见 `cannot execv('/vendor/bin/boringssl_self_test32'): Exec format error` → `reboot_on_failure` | 换 `13.0.0_64only-latest` |
| 2 | `modprobe` 后 `/dev/binder` 唔出现 | 6.8 内核走 binderfs，模块只注册文件系统 | `mount -t binder binder /dev/binderfs` |
| 3 | 容器内 `Permission denied` | binderfs 节点默认 `600` | `chmod 666` |
| 4 | 容器内 `No such device or address`（ENXIO） | `--device` 方式绑节点 | 改 `-v /dev/binderfs/binder:/dev/binder` |

## 15 修云机「存储有问题」（2026-10-26）

**验证**：

|----|------|------|
| `mount | grep ' /data '` | `type virtiofs` | `type ext4 (rw,relatime,discard,errors=remount-ro,commit=30)` |

## 16 实况窗换方案 B：H.264 直播（2026-10-26）

**动机**：A 方案（`screencap` 轮询 + 触控）极限 9 fps、拖拽一跳一跳，老板判「太难用」。

**做法**：`screenrecord --output-format=h264 -` 出 Annex-B → `serve.py` 切 NAL 广播 → 浏览器 `VideoDecoder` 硬解 → `canvas`；触控继续走 `/device/tap|swipe|key`（`frame:false`）。

**踩过的四个坑**

| 坑 | 现象 | 解法 |
|----|------|------|
| 设备只许一路 `screenrecord` | 两个客户端一齐连，第二条冇数据 | 服务端单路编码 + `queue.Queue` 广播；空闲 8 s 收工 |
| 中途接入冇 IDR | `A key frame is required after configure()` | 新客户端 / `?fresh=1` 踢掉编码进程重开；前端遇此错误自动 fresh 重连 |
| Chrome 要 AVCC 唔要 Annex-B | 同上 + `must fill out the description field` | 自己拼 `avcC`，`configure({description})`，每帧 4 字节长度前缀 |
| 静态画面冇帧 | 新开页面空白 | 用 `/screen.png` 做底板；静止 >2.5 s 补一张 |

**实测**

| 指标 | A 方案 | B 方案 |
|------|--------|--------|
| 刷新率 | 0.9–9 fps | **21.5 fps** |
| 发输入 → 画面变化 | 340–450 ms | **277–294 ms**（输入占 240 ms） |
| 码流 | — | 约 2 Mbps（动）、静止 0 |

**验证**：canvas 点击映射 (102,774) → 前台 `com.android.settings/.Settings`；连续滑动 5.2 s 解 112 帧；画面经 vision 复核无花屏/黑屏。

**接口**：`GET /stream`（chunked，帧格式 `[4B len][1B kind][4B ts][payload]`）；`/device/*` 增 `frame:false` 开关。

## 29 云机侧「手」拆开画 + adb forward 泄漏（2026-10-26）

## 34 实操复盘：「下载安装360浏览器」三个症状（2026-10-26）

老板实操三个问题：①步骤日志后段唔再更新 ②都开咗 WebView browser，L1a/L1b 仲系冇出手，落 L2 ③最后几步原地循环、冇动作。

### 34.1 症状①：日志中途停更 —— 真 bug，已修

**根因**：`shell.html` 嘅 `pump()` 里面，`progress` 分支处理 `🔄 Step N/M` 时写 `return` —— 呢个 `return` 唔系跳出分支，而系**直接结束成条 SSE 消费循环**。所以第一行步数写完之后，后面所有事件（含 `result`、`need_hand`）全部收唔到，日志就定镜。系我前一刀加去噪时写落嘅。

**验证**（起 8788 独立实例、6 步预算）：
- 修前：日志定镜喺 `步 1 / 6`，状态条一直显示 `L2 · 转视觉`，130 秒冇再动；同时间服务端其实已经跑完（`/state` phase=human、`/history` 有 result）
- 修后：`步 1→2→3→4→5` 逐个出，`异常` / `轨迹` / `接手` / `失败` 全部见到，`now` 变「卡住 · 要人 · 行 L2」

顺手改两处：
- 异常行唔再当噪音：`Malformed tool-call markup` / `Attempt N failed` / `Error code: N` 用红标 `异常` 显示 —— 之前滤走，等于把病因藏起
- 同一句唔理标签只写一次（之前「思考」同「LOG」会重复两行）

### 34.2 症状③：循环冇动作 —— 模型工具调用格式坏

轨迹实测（`trajectories/20261027_092118_66932df0`）：

| 项 | 数 |
|----|----|
| 模型回应次数 | 4 |
| 真正执行咗嘅工具调用 | **1** |
| 白谂（code 为空 / DSML markup） | 3（75%） |
| 结束原因 | `Model produced malformed tool-call markup 3 consecutive times; stopped to prevent a retry loop. Switch models or verify tool-call protocol compatibility.` |

老板嗰单 20 步：20 次回应、14 次有效工具调用、6 步白烧（30%）。

即系：模型（`workbuddy/deepseek-v4.1-flash` via Qbridge）吐嘅系 `<｜｜DSML｜｜ invoke>` 呢类 markup，Mobilerun 解析唔到 → 当 malformed → 重试 3 次就丢步；轨迹睇落就系「谂完冇做」。加上页面本身（WebView Tester 裸壳下载唔到 APK），就会演成同一个坐标连点。

### 34.3 症状②：L1a/L1b 冇出手 —— 设计如此，唔系 bug

`/layers` 实测：

```
L0  ok=false  why=能力表冇呢句
L1a ok=false  why=冇「动作+目标」可对号入座
L1b ok=false  why=冇 WebView 调试 socket / 页面冇呢个文字
```

两层原因：
1. **L1 只在「整句意图」层试一次**：`route()` 收 `下载安装360浏览器` 试完 L0→L1a→L1b 就交 L2；入 L2 之后每一步都系 Mobilerun 自己 `click`/`click_at`，**L1 再冇入口**。要 L1 介入循环 = 架构改动（自己揸 executor 循环，或给 Mobilerun 插 hook）。
2. **L1 只认「动词 + 1~12 字短目标」**：`下载安装360浏览器` 唔匹配；而且 L1b 检查 socket 嗰刻前台系 Settings / 应用宝，唔系 WebView，所以「冇 socket」—— 等 WebView 开出来嗰阵，已经冇人再问 L1 了。

附带发现（未改，等点头）：L0 嘅「下载/安装 X」正则唔识「下载安装」双动词，所以 `下载安装360浏览器` 会当成名 `安装360浏览器` → 能力表冇呢句；另外机上有应用宝（`com.tencent.android.qqdownloader`），但 agent 先搵 Play Store（唔存在）再落 WebView Tester。

## 37 步骤日志刷新后全空 —— 过程行加服务端副本（2026-10-27）

老板报「个步骤日志又有bug，睇最新一次会话」。现场：14:42–14:52 嘅「下载百度云盘」（16 步，真装好 `com.baidu.netdisk`）跑完之后，步骤日志**一行都冇**，但卡片照显示「完成 · STEP 16/20」、过程图照「做完」，而同一页跟住自己跑 L0 嘅「打开设置」日志就正常出三行。

### 37.1 根因

过程行只由本条 SSE 流实时喂；服务端 `HISTORY` 只存概要（`phase/step/detail/msg`），冇过程行；壳 `loadHistory()` 只重放气泡 + 卡片，`slClear()` 又喺每次 `submit()` 开头清空。所以**只要页面重开过**（reload / 预览窗重挂 / 换客户端），上单卡片照样「完成」而过程行永远唔返 —— 观感等同日志坏咗。

### 37.2 改法（PR-20261027-1 / Issue #3，详细设计 v0.35）

- `serve.py`：`_log_row(event, o, text)` 用**同壳一致嘅规则**把事件翻译成行；`_log_push()` 写落 `HISTORY.<单>.log`（上限 400 行、连续相同去重）；`emit()` / `emit2()` 两个出口都挂上；`CURRENT_TASK` 加 `layer` / `think_step`，令「动作 / 思考」照旧只喺 L2 记
- `shell.html`：`slReplayLast(items)` 开页重放**最后一单**，首行 `重放 · 上一单「…」嘅过程（页刷新前）· N 行`；`#slBody` 已有实时行就唔覆盖；旧数据冇 `log` 出一行 `提示 … 服务端未存过程行`
- 文档 v0.35（§3.4.16 + 变更历史）+ HTML 重生

### 37.3 实测（真跑）

| 验法 | 结果 |
|---|---|
| `_log_row` 直调 13 例 | L0 下 `activity` 返 None；L2 下 action/think 出行、同一步重复 think 只记一次；`Malformed…` → `异常`；`[PostHog]` → 滤走；`🔄 Step 3/20` → `步`；`result` → 完成/失败；`need_hand` → 接手；`layer` 行带 cmds/ms/why |

## 38 卸载走 L2 —— L0 解析唔食「掉/吧」（2026-10-27）

老板火：「我一个卸载应用的动作，走了 L2？明明就 L0 一句 adb uninstall 命令的事情」。

现场：`/history` 任务「卸载掉360浏览器吧」`phase=done 6/20`，步骤日志见 6 步 L2（开应用列表 → 应用详情 → 点 UNINSTALL → 确认 OK → 判断消失），`/layers` 写 `L0 ok=false why=能力表冇呢句`。

### 38.1 根因（三个同时成立）

| # | 原因 | 实证 |
|---|------|------|
| 1 | `clean()` 唔清句尾语气词（NOISE 只见 啦/呀/下） | `clean("卸载掉360浏览器吧")` → 原样，抓出「360浏览器吧」 |
| 2 | 卸载正则 `^(?:卸载\|删掉\|移除)\s*(.+)$` 唔食补语 | 正则 group = `掉360浏览器吧` → `resolve_package` 返空 |
| 3 | 别名表冇 360浏览器，包名 token 又对唔上（`360浏览器` 唔系 `com.qihoo.browser` 子串） | `resolve_package("360浏览器")` 返空 |

三层一齐 miss 就落 L2。另外发现 `installed()` 有 60 s 缓存，卸完唔清会继续报「已装」。

### 38.2 改法（详细设计 v0.36）

- `NOISE` 补 `吧/啊/嘛/咯/囉`
- 卸载 / 关 app / 清数据 正则加 `(?:掉|咗|了|甩)?`
- `APP_EXTRA` 补 360浏览器 / 360 / 奇虎360 / 百度网盘 / 百度云盘 / 百度云 / 腾讯视频 / 爱奇艺 / 优酷
- **确定性动作判定**：卸载查唔到包名 → L0 即报「包表冇 X + 机上第三方清单」`final=true`，唔落 L2；指代词（这个/呢个/佢/当前…）才交 L1/L2 睇屏幕
- 卸完 `_INSTALLED["pkgs"].discard(pkg)`
- `serve.py` LAYERS_DOC L0 触发句补「卸载/清数据」
